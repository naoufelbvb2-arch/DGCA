## 1. Purpose & Scope

RIC-03-C01 is a narrow architectural correction to RIC-03 addressing three identified defects:
1. **Public Nonce Parameter Pollution:** Public `CanonicalSystemRuntime.fresh()` and `from_checkpoint()` permitted injection of `learning_session_nonce`, violating the invariant that AUTO occurrence identity must always be freshly generated by host runtime boot and restore.
2. **Volatile Mutual Exclusion Deficiency:** Concurrency control relied on single-attribute check/set rather than a real non-blocking host-side lock (`threading.Lock()`), leaving race windows open under concurrent thread execution.
3. **Public Authority Surface Leakage:** Public property `learning_runtime` on `CanonicalSystemRuntime` and public property `authorizer` on `CanonicalLearningRuntime` exposed internal authority structures beyond the canonical user API (`learn()`).
4. **Verification Provenance Discrepancy:** The initial verification report recorded an unresolvable pre-amend commit hash (`01e9643...`) rather than the authoritative implementation commit `529ecf6e018996d0358380ab66f627b81acd09bd`.

No cognitive learning laws, graph topologies, R1/R2 protocols, or checkpoint schemas are modified.

## 2. AUTO Identity & Restore Lifecycle Invariants (C01-G01)

### 2.1 Internal Nonce Generation
- Production methods `CanonicalSystemRuntime.fresh()` and `CanonicalSystemRuntime.from_checkpoint()` do not accept `learning_session_nonce`.
- Every fresh boot and every checkpoint restore generates a new, cryptographically random 12-character hex nonce (`secrets.token_hex(6)`).
- Deterministic nonce injection is restricted strictly to private test-only factory methods:
  - `CanonicalSystemRuntime._for_test(..., learning_session_nonce=...)`
  - `CanonicalSystemRuntime._from_checkpoint_for_test(..., learning_session_nonce=...)`

### 2.2 Fresh Nonce After Restore
Let $R_A$ be a runtime instance with session nonce $N_A$, and let $R_B$ be a cold-restored instance from a checkpoint saved by $R_A$.
1. $N_A \neq N_B$ (strict inequality).
2. For any AUTO learning exposure on $R_A$ with key $K_A = \text{auto}:N_A:1$, and any AUTO learning exposure on $R_B$ with key $K_B = \text{auto}:N_B:1$:
   $K_A \neq K_B$.
3. When the same text is presented via AUTO mode after restore, $R_B$ executes the observation as a new `PERSISTENT_EXECUTED` exposure with a distinct persistent transaction ID.
4. **Identity Policy:**
   - **`AUTO` Identity:** Represents volatile process/session exposure episodes (reinforcement semantics).
   - **`EXTERNAL` Identity:** Represents stable external identifiers surviving checkpoints (idempotent replay semantics).

## 3. Real Thread-Safe Operation Mutual Exclusion (C01-G02)

### 3.1 Host-Side Operation Lock
`CanonicalSystemRuntime` holds an internal `threading.Lock()` instance in slot `_lock`.
- **Volatile Host State:** The lock is host engineering state only; it is never serialized, never checkpointed, and excluded from state digests.
- **Non-Blocking Acquisition:** Acquisition is performed via `self._lock.acquire(blocking=False)`.
- **Fail-Closed Semantics:** Any attempt to invoke `chat()`, `learn()`, or `save_checkpoint()` while another canonical operation holds the lock fails closed immediately by raising `RuntimeError`.
- **Zero Indefinite Blocking:** Callers never hang or deadlock.

### 3.2 State Lifecycle & Cleanup
1. `_acquire_operation(state)`:
   - Evaluates `self._lock.acquire(blocking=False)`.
   - If acquired: sets `self._operation_state = state`.
   - If failed: raises `RuntimeError(f"Cannot begin operation '{state.value}': runtime is currently in state '{self._operation_state.value}'")`.
   - If reentrant `CHATTING` during `CHATTING`: message includes `"(Single active turn violation: another turn is currently running)"` for backwards compatibility with R3-Min suites.
2. `_release_operation()`:
   - Sets `self._operation_state = SystemOperationState.IDLE`.
   - If `self._lock.locked()`: calls `self._lock.release()`.
   - Guaranteed executed via `finally` in `chat()`, `learn()`, and `save_checkpoint()`.

## 4. Narrow Authority Surface (C01-G03)

1. **`CanonicalSystemRuntime.learn()`** is the sole canonical host-facing persistent learning API.
2. The public property `CanonicalSystemRuntime.learning_runtime` is removed. Internal access is strictly through private field `self._learning_runtime`.
3. The public property `CanonicalLearningRuntime.authorizer` is removed. Internal access is strictly through private field `self._authorizer`.
4. `CanonicalLearningRuntime` does not expose `capability` or `_capability` publicly.
5. `LearningResult` exposes no capability, authorizer, graph, or ledger object.
6. `CognitiveAgent` exposes no learning methods, properties, or authority tokens.
